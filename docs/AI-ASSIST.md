# AI 助手

文舟可以接入用户自己的 AI 服务：把选定章节整理成术语库、大纲与关系、地图等辅助文件，并在写作时给出淡色的续写建议。功能默认关闭；内容只在用户操作时直接发往用户选择的服务，不经过开发者。

架构决定见 [ADR 0009](adr/0009-ai-assistant.md)。本文是功能与实现说明，按阶段更新。

## 服务与密钥

### 支持的服务

四种请求格式覆盖常见服务。预设只填好接口地址和常用模型，用户可以改。

| 请求格式                                                   | 预设                                                                                                                                                                                           |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OpenAI 兼容（`/chat/completions`）                         | OpenAI、DeepSeek、通义千问（百炼兼容模式）、Kimi（月之暗面）、智谱 GLM、豆包（火山方舟）、百度千帆、腾讯混元、硅基流动、OpenRouter、Mistral、xAI、Groq；本机或自建：Ollama、LM Studio、vLLM 等 |
| Anthropic（`/v1/messages`）                                | Anthropic Claude                                                                                                                                                                               |
| Gemini（`generateContent`）                                | Google Gemini                                                                                                                                                                                  |
| Azure OpenAI（部署地址 + `api-version`，`api-key` 请求头） | Azure OpenAI                                                                                                                                                                                   |

“自定义”可选任一格式并填写接口地址。地址必须是 HTTPS；`localhost`、`127.0.0.1` 和局域网地址允许 HTTP，便于连接本机模型。

### 设置

设置 → AI 助手：

| 项目           | 说明                                                                                                           |
| -------------- | -------------------------------------------------------------------------------------------------------------- |
| 启用 AI 助手   | 总开关，默认关闭。关闭时不显示 AI 按钮、不发请求                                                               |
| 服务、接口地址 | 选预设或自定义                                                                                                 |
| 模型           | 整理文件与续写建议分别选择：整理适合能力强的模型，续写适合快而便宜的模型                                       |
| API Key        | “验证并保存”先发一次最小请求，成功才保存；保存后只显示“已保存 · 末 4 位”，可删除，不能再查看。本机模型可以不填 |
| 单次发送确认   | 超过设定字数时先确认（默认 2 万字）                                                                            |
| 每日上限       | 可选，按发送字数统计，到达后暂停直到次日                                                                       |

首次启用时说明：内容会发给哪个服务、适用该服务的隐私政策、文舟开发者看不到也不保存这些内容；用户确认后才开启。

### 密钥只在原生层

沿用 Git 令牌的做法（`CredentialStore`）：

- 安卓用 Android Keystore 加密保存，鸿蒙用系统安全凭据存储（Asset Store），Windows 用 Electron `safeStorage`。
- 前端只能通过原生调用 `ai` 让原生层代发请求，拿不到 Key 明文。
- Key 与保存时的接口地址（协议、主机、端口、路径前缀）绑定。改了接口地址就要重新输入 Key，原生层不会把 Key 发到别的地址。
- 接口地址最多 400 个、Key 最多 512 个可打印 ASCII 字符（国际化域名用 punycode）。这样“格式 + 地址 + Key”整条记录不超过鸿蒙 Asset Store 单条密钥的 1024 字节，三端都直接存入系统安全存储，不另加一层加密。
- 原生层只放行所选请求格式的固定路径：生成接口和验证用的模型列表接口。
- Key 不写日志，不进备份、同步、导出和崩溃信息。
- 浏览器预览版只用于开发和测试：Key 只保存在当前页面内存中，刷新即清除；请求由浏览器直接发出，部分服务会因跨域限制拒绝。

## AI 按钮与面板

- 启用且已配置后，编辑 TXT、Markdown 时编辑区右上角悬浮 AI 按钮；预览、阅读、地图、大纲等页面不显示。窄屏放在顶栏下方，不遮挡章节目录；可在面板里选择收进“更多”菜单。
- 面板宽屏从右侧滑出，窄屏从底部弹出。顶部固定显示“内容将发送给 <服务> · <模型>”。
- 面板分“整理辅助文件”和“续写建议”两部分。

## 整理辅助文件

1. **选择章节**：列出当前文稿的章节（沿用章节识别），可单选、连选或全选，显示字数。
2. **选择产物**（可多选）：
   - 术语库 `.gly`：人物、地点、势力、物品、设定，含分类、别名和一句话释义。
   - 大纲与关系 `.pcs`：按章或按事件生成大纲节点；“关系”视图里人物为节点，关系为带标签的连线。
   - 地图 `.vlmp`：只生成信息点（名称、备注、互相链接），按文中方位粗略排布，不画地形；预览中注明“位置仅供参考”。
3. **发送前确认**：列出章节、字数和产物；超过单次确认字数或接近每日上限时强调提示。
4. **生成**：长篇分批（每批不超过所选模型上下文的安全比例），每批产出部分结果，最后合并去重。显示进度，可取消；取消后不写任何文件。
5. **校验**：AI 输出只接受约定的 JSON 结构，再经过各格式现有的校验（数量、大小、重复、路径）。不合格的条目丢弃并说明原因。
6. **预览与合并**：结果作为草稿逐条显示，可勾选、修改。已关联的术语库或大纲按名称和别名比对，标出“新增 / 与现有不同 / 已存在”。确认后合并到现有文件或新建文件；新建的术语库自动加入作品 `.vela` 的 `editor.glossaries`。合并整体可撤销。

AI 生成的文件与手写文件相同，走现有保存与同步。

## 续写建议

### 显示

- 开关在面板里，默认关闭，按作品记住。
- 停止输入约 1 秒、光标位于段尾、没有选区时请求；建议一般是一两句，最多约 60 字。
- 用 CodeMirror 装饰显示在光标后，透明度约 35%，字号、字体与正文相同。建议不写进文稿，不进入撤销记录，不保存、不同步、不导出。

### 与输入共存

- **中文输入法**：组合输入期间不请求、不显示；组合开始时立即隐藏已有建议。
- **继续输入**：输入与建议开头一致时保留剩余部分，否则清除并取消进行中的请求。
- **术语补全**：补全弹窗出现时隐藏建议，补全优先。
- **只读、预览、项目锁定**时不显示。

### 接受与拒绝

| 方式     | 键盘（含平板外接键盘）                            | 触屏                   |
| -------- | ------------------------------------------------- | ---------------------- |
| 接受整段 | `Tab`（仅在建议显示时；否则仍是缩进两个全角空格） | 点按淡色建议文字       |
| 接受一句 | `Ctrl+→`（按句读 。！？…… 切分）                  | 建议末尾浮条“接受一句” |
| 拒绝     | `Esc`，或继续输入不同内容                         | 浮条“×”，或继续输入    |

触屏浮条贴在建议文字下方，三个按钮至少 40px 高，避开软键盘；点按正文其他位置也会收起建议。

### 上下文与用量

- 默认发送光标前约 2000 字和本章标题；只发光标之前的内容。
- 可选附加：当前片段中出现过的关联术语库词条（保持人名、设定一致）；本章对应的大纲节点。
- 防抖、同一位置不重复请求、新输入取消旧请求、每分钟次数上限；失败静默退避，面板显示最近错误；离线时暂停。

## 实现

| 模块                   | 职责                                                                                                       | 加载           |
| ---------------------- | ---------------------------------------------------------------------------------------------------------- | -------------- |
| `web/ai-providers.mjs` | 服务预设、四种请求格式的请求构造与响应解析                                                                 | 随 AI 功能按需 |
| `web/ai-client.mjs`    | 统一 `complete({purpose, messages, signal})`；原生端走 `transport('ai')`，浏览器预览直接 `fetch`；用量统计 | 按需           |
| `web/ai-settings.mjs`  | 设置页“AI 助手”一节                                                                                        | 打开设置时     |
| `web/ai-panel.mjs`     | AI 按钮与面板                                                                                              | 启用后首次使用 |
| `web/ai-extract.mjs`   | 分批、提示词、JSON 解析、合并与格式转换                                                                    | 首次整理时     |
| `web/ai-suggest.mjs`   | CodeMirror 续写扩展：防抖、输入法、装饰、接受与拒绝                                                        | 开启续写时     |

原生调用 `ai`（三端）：

| 动作      | 说明                                                                                          |
| --------- | --------------------------------------------------------------------------------------------- |
| `status`  | 是否已保存 Key、末 4 位、绑定的接口地址                                                       |
| `save`    | 校验地址与格式后保存 Key（先由前端用 `verify` 验证）                                          |
| `verify`  | 用待保存的 Key 请求模型列表或一次最小生成                                                     |
| `clear`   | 删除 Key                                                                                      |
| `request` | 只接受固定路径与 JSON 请求体；附上 Key 发往绑定地址；返回状态码与 JSON；支持 `requestId` 取消 |
| `cancel`  | 取消某个 `requestId`                                                                          |

第一版不做流式输出：续写是短文本，整理按批进行。

## 隐私

`docs/PRIVACY.md` 与应用内隐私说明增加“AI 助手”一节：功能可选、默认关闭；只在用户操作时发送其选定的章节或光标前设定范围的文字；直接发往用户配置的服务，适用该服务的条款；Key 保存在系统安全存储。上架时按应用市场要求更新数据处理申报。

第一版不向插件开放 AI 调用。
