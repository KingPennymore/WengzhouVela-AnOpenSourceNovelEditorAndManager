# 前端改进方案（0.9.7 之后）

状态：A 级与 B 级已实现（2026-10-15，见第 7 节），C 级未做。依据 2026-10-15 对当前前端的截图检查（桌面 1366×820、手机 390×844、浅色与深色）和实测尺寸。截图生成脚本可按需重跑，结果不入库。

## 1. 结论

现有视觉风格是对的，不建议推倒重来：
- 低饱和的“纸张”配色、强调色只做点缀、圆角卡片和细分隔线，三端一致，阅读页排版干净。
- 新增的格式、注音、样式也能自然融入这套风格。

问题主要出在**编辑页的壳层**：工具栏层数太多，正文让位给了控件。建议分三级推进：
- **A 级**：小修，不改结构。
- **B 级**：重排编辑页壳层，这是本方案的重点。
- **C 级**：重做启动页。

建议先做 A 和 B；C 可以等有写作统计数据后再做。

## 2. 检查发现

### 已在本次修复

| 问题 | 原因 | 修复 |
| --- | --- | --- |
| 深色模式下顶栏导航组、侧栏和标签的分隔线是浅色的，很刺眼 | `--hairline: var(--line)` 定义在 `:root`，而配色变量写在 `body` 的内联样式上，`--hairline` 在 `:root` 就按浅色算定了 | 改为在 `body` 上定义（`web/design.css`） |
| “更多”菜单、快捷键说明和操作指南里还写着“Acode 插件” | 移除 Acode 运行时时漏改 | 改为“插件与组件”，指南改为插件接口 4 的说明 |
| 格式栏的“样式”下拉框是系统默认外观，被拉到 140px 宽 | 全局 `select{width:100%}` 生效 | 改为与格式按钮同高的紧凑下拉框 |
| 配色编辑器里的标签被挤成一字一行 | 全局 `#dialog-body input` 把颜色框拉满了宽度 | 颜色框固定宽度，标签不换行 |

### 待改进

1. **工具栏层数多，正文区只占 75%**。编辑页从上到下是：顶栏 51px、标签栏 39px、格式栏 34px、正文、底部快捷栏 52px、状态栏 28px。桌面和手机上，正文区都只占窗口高度的 75%。写小说是长时间盯着正文的场景，这个比例偏低；同类写作工具通常在 85% 以上。
2. **桌面端的底部快捷栏与键盘重复**。保存、撤销、重做、到顶、到底、章节首尾这些按钮在桌面上都有快捷键，常驻一条 52px 的大按钮栏性价比不高。手机上保留它是合理的。
3. **小说模式显示行号**。TXT 一个段落常折成多行，行号对写作没有帮助，还占宽度：桌面 52px，手机 38px（约占屏宽 10%）。
4. **格式栏是两套**。Markdown 一套、TXT 一套，都是文字按钮，没有分组；手机上被截断。选中文字时已经会弹出选区菜单，但菜单里没有格式项。
5. **手机上标签栏与视图切换挤在同一行**，文档标签与“文本 / 源码 / 预览”互相遮挡（截图中“文本”被盖住了一半）。
6. **启动页信息密度低**：
   - 三张统计卡（本地文件 / 工作区 / 阅读文件，示例中都是 2）对写作没有帮助。
   - 7 个入口同等大小，最常用的“继续写最近的文稿”反而要点两次（最近文件 → 文件）。
   - 宽屏上内容只占中间 650px。
7. **书库页的对齐不一致**：标题和搜索框从 x≈233 开始，书卡从 x≈55 开始。封面只是一个“TXT”色块，作品配置里有封面时也没有用上。
8. **命令面板**：项目平铺、没有分组，快捷键不显示在条目右侧，命令一多不好找。
9. **阴影的色调固定为青绿**（`#0f2418`），换成麦田、石墨或自定义配色后阴影会偏色。

## 3. 设计原则（延续现有风格）

- **正文优先**：控件只在需要时出现；能用快捷键、选区菜单完成的，不常驻成大按钮。
- **一处入口**：同一个操作只有一个主要入口，其他入口是快捷方式（例如格式：选区菜单为主，格式栏为辅）。
- **配色只来自变量**：颜色、阴影、分隔线全部来自配色变量，自定义配色在任何界面都不偏色。
- **三端一致**：同一份网页前端；手机只调整布局（底栏、抽屉），不另做一套交互。

## 4. 方案

### A 级：小修（不改结构）

| 项目 | 做法 |
| --- | --- |
| 阴影随配色 | `--elev-*` 改用由 `--text` 推导的半透明色，深色模式保持现状 |
| 小说模式默认隐藏行号 | TXT 小说模式默认不显示行号，设置里可以打开；代码模式和其他格式不变 |
| 格式栏图标化 | 两套格式栏统一为图标按钮，按“字形 / 段落 / 插入 / 样式”分组，组间加细分隔，悬停提示里带快捷键 |
| 选区菜单加格式 | 选中文字后的菜单里加粗体、着重号、注音、样式（`selection-menu.mjs` 已支持 `extraItems`） |
| 书库对齐 | 标题、搜索框和书卡共用同一条左边线；作品配置有 `project.cover` 时用作封面 |
| 命令面板分组 | 分为“文稿 / 格式 / 导出 / 视图 / 工作区”，右侧显示快捷键 |
| 手机标签栏 | 视图切换移到格式栏右端，标签栏独占一行 |

### B 级：编辑页壳层重排（推荐）

目标是正文区占比从 75% 提高到桌面约 88%、手机约 82%：

```
现在（桌面）                          方案
┌──────────────────────────────┐      ┌──────────────────────────────┐
│ 顶栏 51                       │      │ 顶栏 51（导航、文件名、保存状态）│
├──────────────────────────────┤      ├──────────────────────────────┤
│ 标签栏 39                     │      │ 文稿栏 40：标签 │ 格式组 │ 视图 │
├──────────────────────────────┤      ├──────────────────────────────┤
│ 格式栏 34                     │      │                              │
├──────────────────────────────┤      │                              │
│                              │      │            正文               │
│            正文 615           │      │          约 720              │
│                              │      │                              │
├──────────────────────────────┤      ├──────────────────────────────┤
│ 快捷栏 52                     │      │ 状态栏 28：章节 · 字数 │ ↶ ↷ ⤒ ⤓ │
├──────────────────────────────┤      └──────────────────────────────┘
│ 状态栏 28                     │
└──────────────────────────────┘
```

- **文稿栏**：标签栏和格式栏合并为一行。左边是标签，中间是当前格式的工具组（TXT、Markdown 各自显示），右边是“文本 / 源码 / 预览”。宽度不够时，格式组收进一个“格式”按钮的下拉面板。
- **桌面端去掉底部快捷栏**：撤销、重做、章节跳转改成状态栏右侧的小图标，保存状态已经在顶栏。手机端保留底栏，因为这是拇指能够到的区域。
- **专注模式**（已有）在这个基础上进一步隐藏顶栏和文稿栏，只留正文和一条极细的状态行。
- **插件**：“文稿工具区”插槽改为挂在文稿栏的格式组之后，底栏插槽在桌面上并入状态栏。插件接口 4 的插槽名称和行为不变，已有插件不需要修改。

风险与对策：
- 已有约 20 个浏览器测试按现有 DOM 结构定位按钮。按钮 ID 保持不变，只移动所在容器。
- 手机和平板的断点（≤600px、≤900px）要逐一截图核对。

### C 级：启动页重做（可选）

- 顶部放一张“继续写作”卡：最近的文稿、所在章节、本章字数和一个“继续”按钮，一次点击直接回到上次的光标位置。
- 下面一行三个常用动作：新建、导入、Git 仓库。“操作指南、命令、插件、设置”收进次级列表。
- 统计卡改为写作统计（今日字数、本周字数）。这需要新增按天记录的字数数据，属于新功能，建议单独评估。

## 5. 不建议做的

- **整体更换视觉风格**（例如改成 Material 或高饱和色）：会破坏三端一致和现有配色系统，用户还要重新适应，收益不明显。
- **为手机另做一套界面**：维护成本翻倍。现在的同一前端加断点布局已经够用。

## 6. 建议顺序

1. A 级全部，约 1–2 天，基本不影响现有测试。
2. B 级壳层重排，约 3–5 天，需要同步调整浏览器测试和三端截图验收。
3. C 级视写作统计功能再定。

## 7. 实施记录（A 级、B 级）

| 项目 | 结果 |
| --- | --- |
| 阴影随配色 | 浅色模式的 `--elev-*` 由配色的文字色推导（`palettes.mjs`），深色模式保持黑色阴影 |
| 行号 | TXT 小说模式默认不显示；设置“编辑 → 小说模式显示行号”可打开；代码模式和其他格式不变 |
| 工具栏 | Markdown 与 TXT 两套格式按钮统一为同一套 24 格线条图标（18px、相同描边），按钮 30×30（窄屏 28×28），组间细分隔；下拉框与按钮同高；每个按钮都有名称和带快捷键的提示 |
| 选区菜单 | TXT 选中文字时提供粗体、着重号、注音 |
| 命令面板 | 分为文稿与导出、TXT 格式、外观、写作工具、界面与快捷键、插件；搜索时在条目右侧显示所属分组 |
| 书库 | 标题与书架共用 1100px 宽度和同一左边线；作品配置有 `project.cover` 时在原生端显示封面图 |
| 文稿栏（B） | 宽于 900px：标签、格式工具、视图切换合为一行；底部快捷栏的按钮移入状态栏右侧（小图标，文字只在提示中）。窄屏：标签独占一行，格式工具与视图切换在正文上方一行，格式按钮区可横向滚动、视图切换固定可见；没有格式工具的文稿把视图切换留在标签行；底部快捷栏保留。窗口跨过 900px 时实时切换，按钮 ID 与事件不变 |

实测正文区占窗口高度：1366×820 从 75% 提高到 85%，1024×768 为 85%，901×700 为 83%；768×1024 为 80%，390×844 为 75%，与改动前相同（窄屏只是把格式栏换成工具行）。手机端若要继续提高，需要合并状态栏与底栏，留待后续评估。

插件接口 4 的插槽名称和行为不变：文稿工具区插槽跟随格式工具，底栏插槽在宽屏下随快捷按钮进入状态栏。

测试：`tests/shell-layout-browser.mjs`（宽窄屏结构与实时切换、正文占比、按钮名称、行号开关、选区菜单格式、命令分组、阴影、书库对齐）。`tests/browser.mjs` 的两处断言按新行为更新：快捷按钮在宽屏下位于状态栏；TXT 小说模式默认不显示行号。
