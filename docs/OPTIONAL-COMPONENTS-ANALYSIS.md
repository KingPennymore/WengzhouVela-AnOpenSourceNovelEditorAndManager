# 当前功能的可选组件拆分分析

更新：电子书组件现已加入 PDF 阅读（约 2.1 MiB ZIP），ODF 已按用户要求拆成独立文档组件。下面原体积表是首次拆分分析的历史测量；其中“PDF 下一步独立拆分”“保留基础 VODT 编辑”的建议已经被本次实现替代。当前宿主仅保留 ODF 纯文本/源码回退、模板和格式注册，ODF 渲染、图片、导出引擎随组件加载。TeX PDF 预览依赖仍在宿主，不能将电子书组件体积宣称为宿主净节省量。开发与限制见 [ODF-COMPONENT.md](ODF-COMPONENT.md)。

对象：用户提供的 WengzhouVela 0.9.5 源码与本次组件修订。结论来自当前代码、构建依赖和资源字节数，未在本次任务中额外拆分下列功能。MiB = 1048576 字节；表中是未压缩前端资源或 bundle 贡献，不是 APK/HAP/安装包净节省量。实际压缩、共享依赖、原生壳和字体缓存会改变收益，不能简单相加。

## 优先结论

已有 TeX 引擎/中文可选包是最大的空间优化。本次新增电子书阅读器使用普通插件组件协议，仅约 29.2 KiB ZIP，未加入主应用 app.js。接下来建议依次拆出：PDF 高级阅读、中文名词提取与自动候选、多语言代码编辑、Markdown 数学公式。基础小说编辑、文件/项目管理、本地历史、配置与 GitHub/Gitee 同步应留在宿主。

## 推荐的发行方式

- 基础版：TXT/Markdown、基础 VODT、章节/术语库、本地历史、文件与项目管理、GitHub/Gitee、轻量文本阅读，以及插件管理器。
- 推荐组件：EPUB/FB2/MOBI7 阅读、PDF 阅读、中文候选、数学公式。
- 专业组件：TeX 离线编译 + 中文宏包/字体、代码编辑扩展；未来可追加高级分页排版、格式转换。

用户应能选择“完整版”预装组件或“基础版”按需安装。完整安装包里的资源不能通过删除卡片卸掉；必须把可卸载资源安装到应用数据目录。停用改善运行负担，卸载数据组件才减少已安装组件占用，两者不要混用宣传。

## 真正拆分还需要的宿主机制

1. **依赖图与声明。** 在未来独立组件清单增加宿主支持的 depends/requires 声明，并校验 API 版本、平台能力和资源摘要。当前 v3 的 requiredCapabilities 只检查宿主能力，不是组件依赖系统；此修订没有实现 depends。TeX/PDF、代码语言/编辑器等依赖必须在启停前检查。
2. **格式注册。** 提供宿主级 reader/editor/exporter 注册接口，定义扩展名、MIME、二进制输入、章节/书目、打开/关闭、进度和错误协议。现在电子书是插件页独立阅读，没有接管主阅读视图或系统默认文件关联。
3. **一致的安装事务。** 大资源用 IndexedDB/原生文件，不使用 localStorage/base64 全量 JSON；分组替换、失败回滚、版本绑定、临时文件清理要统一。旧版本资源可以保留至切换成功，再清理缓存。
4. **停用保证。** 先取消任务、释放 Worker/URL/事件，再移除能力。组件执行时拒绝启停或给出取消选项；卸载不得删除用户书籍、写作项目或源码。
5. **缺失组件体验。** 用户打开已知格式时展示文件信息、纯文本可读内容（如可安全提取）和明确安装入口；不要把二进制书籍作为乱码文本保存。
6. **按需构建与测试。** 组件必须从宿主 bundle 和资源拷贝清单中消失，依赖/license 也随包生成。增加“未安装 / 已安装 / 已停用 / 卸载 / 版本不匹配 / 启停中取消 / 重启 / 空间不足”测试，再测三端最终安装包。

PDF 和数学资源可采用与 TeX 类似的宿主固定摘要资源协议；可独立执行的业务界面可采用本次电子书的插件组件协议。当前只实现两种现有路径，尚未把全部模块改成通用组件框架。

## 测量方法与验证范围

此修订用 esbuild.metafile 的 bytesInOutput 统计共享 app.js 的依赖贡献，以文件实际长度统计 dist/web 的 Worker、CMap 和字体资源，以 ZIP 文件实际长度统计发布组件。测量记录在本次验证的 resource-sizes.json 和 bundle-size.json；源码包内另有验证说明。

共享前端检查可以证明逻辑与浏览器流程，不替代鸿蒙/Android/Windows 原生系统选择器、权限和发布包体验验收。本次提供源码及可安装组件 ZIP，未生成或签名新的 HAP/APK/EXE。
