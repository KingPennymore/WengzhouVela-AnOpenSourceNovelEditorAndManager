# .vela 第三版：TXT 正文 + 作品配置中的格式

状态：已实现，见第 9 节。0.9.7 把格式写在每个 TXT 旁的旁注文件里；0.9.8 起格式并入作品 `.vela` 的 `richText`，条目改为按行定位（第 3 节、第 10 节）。现行配置格式见 [VELA.md](VELA.md)。

## 1. 目标与结论

目标：在不改变 TXT 正文的前提下，让文舟能编辑和显示富文本（粗体、着重号、注音、居中、插图等）。

- 正文仍是纯 TXT：其他编辑器、网文平台后台、Git diff、“导出章节文本”看到的都是干净的文字。
- 格式写在作品配置 `.vela` 的 `richText.documents` 里（0.9.7 为同目录的旁注 `正文.txt.vela`），随作品同步、移动、备份。
- 在文舟里编辑时，格式随文字精确移动（CodeMirror 的 RangeSet 映射）；在文舟外改了正文，打开时按“所在行的摘要 + 原文”重新定位，定位不了的格式不会被丢弃，而是列入“待确认”。

**结论：可行。** 文舟已有同类基础：书签和批注就是正文外的锚点（`remapAnchors` / `resolveAnchor`，见 `web/document-service.mjs`），编辑器是 CodeMirror 6，原生支持装饰映射与可撤销的状态效果。主要风险不在编辑器，而在“文舟外部改稿后的重定位”和“文件操作的长尾”（重命名、移动、回收站、历史、同步都要带上旁注），见第 7 节。

## 2. 为什么是“TXT + 旁注”

| 方案 | 问题 |
| --- | --- |
| 在 TXT 里写标记（类 Markdown） | 污染正文；`*`、`#` 在小说中常见；复制到平台要先清洗 |
| 直接用 Markdown 文稿 | 已支持，但同样是“标记在正文里”，且没有注音、着重号等 |
| 单文件富文本容器（原 VODT/FODT） | 已删除；XML/Base64 不利于 Git 合并，外部编辑器不可读 |
| 写进作品 `.vela` | 0.9.7 未采用：配置上限 256 KB、条目体积大。0.9.8 改用：上限只约束配置部分，条目按行定位、每条一行，体积约为旁注的六分之一（见第 10 节） |
| 写进应用私有数据（像批注那样） | 不进 Git、不随文件夹复制，换设备格式丢失；格式是作品内容，必须跟文件走 |

0.9.7 选用每个 TXT 一个旁注文件；0.9.8 起改为写进作品 `.vela`。没有格式的 TXT 与现在完全一样。

## 3. 第三版 `.vela` 的组成

第三版沿用第二版的 `global` 与 `workspace`。与编辑格式有关的内容都在 `richText` 中：

| 文件 | kind | 第三版变化 |
| --- | --- | --- |
| 根目录 `.global.vela` | `global` | 可选 `richText.enabled`、`richText.styles`（个人默认） |
| 文件夹 `.vela` | `workspace` | 可选 `richText`：`enabled`、`styles`、`documents`；用到时写 `version: 3` |
| `<文件名>.txt.vela` | `document` | 0.9.7 的旁注，只读取、不再新建 |

在 `.vela` 编辑页中，“作品配置”和“TXT 格式”是同一个文件的两页。没有作品 `.vela` 的 TXT 第一次保存格式时，文舟在它所在的文件夹新建一个 `.vela`；这个 `.vela` 不写阅读清单（`reading.items`），文件夹内全部文稿照常出现在书库中。

版本策略：解析器同时接受 2 和 3。0.9.9.9 起，**新建配置与检测到的有效旧配置统一写为第三版**；转换前原文保留到普通本地历史中，损坏或未来版本配置不自动改写。旧版文舟遇到 `version: 3` 会按现有规则提示版本错误并保留原文，不会损坏文件。

### 3.1 作品配置新增字段

```json
{
  "version": 3,
  "kind": "workspace",
  "id": "my-novel",
  "richText": {
    "enabled": true,
    "styles": {
      "system": {"label": "系统提示", "block": true, "align": "center", "frame": true},
      "letter": {"label": "书信", "block": true, "font": "kai", "indent": 2}
    },
    "documents": {"正文.txt": {"text": {"length":42,"hash":"a33fdc08","lines":7}, "marks": []}}
  }
}
```

- `richText.enabled`：为本作品的 TXT 打开格式工具栏；`false` 时即使本机开了“TXT 格式工具”也不显示（已有格式的 TXT 仍显示）。
- `richText.styles`：作品级**命名样式**（0.9.7 写在顶层 `styles`，仍可读取，修改样式时移入 `richText.styles`），如“系统提示”“书信”“回忆”，用于网文常见的系统面板和书信体。编辑器、阅读页、导出共用同一份定义。样式属性用封闭集合（对齐、缩进、字体族、框线、字号档位、颜色档位），不接受任意 CSS。

### 3.2 格式记录 `richText.documents`

0.9.8 起，每个 TXT 的格式是作品 `.vela` 中 `richText.documents` 的一项，键为相对 `.vela` 所在文件夹的 TXT 路径：

```json
"richText": {
  "documents": {
    "卷一/正文.txt": {
      "text": {"length":24938,"hash":"9f2c41d0","lines":812},
      "marks": [
        {"type":"strong","at":[3,2,6],"hash":"cb9d9ce8","quote":"林舟冷笑"},
        {"type":"emphasis","at":[5,8,10],"hash":"a433712e","quote":"不好"},
        {"type":"ruby","value":"sū wǎn","at":[5,2,4],"hash":"a433712e","quote":"苏晚"},
        {"type":"strong","at":[9,4,5],"hash":"5be0a1c2","quote":"好","prefix":"　　好，","suffix":"，好。"}
      ],
      "blocks": [
        {"type":"align","value":"center","at":[7],"hash":"2ba039cb","head":"——完——"},
        {"type":"style","value":"system","at":[12],"hash":"77c0e3d1","head":"【叮！任务完成】"}
      ],
      "inserts": [
        {"type":"image","src":"插图/01.png","alt":"雪夜山门","at":[40],"hash":"0be41a7f","head":"　　灯火摇晃。"}
      ]
    }
  }
}
```

规则：

- **按行定位**：`at` 为 `[行, 起, 止]`（行从 1 起，列为 UTF-16 码元，基于统一为 LF 的正文）；跨行的行内格式为 `[行, 起, 末行, 止]`；段落格式和插图为 `[行]`，插图位于该行之后。
- **`hash`**：所在行的 8 位 FNV-1a 摘要。外部改稿后，没改的行凭摘要找回，无论它被移到哪里。
- **`quote` / `head`**：行内格式覆盖的原文、段落开头最多 12 个字，用来确认位置。`prefix` / `suffix`（行内各 8 字）只在原文在本行出现不止一次时写出。
- **`text`**：保存时正文的长度、摘要和行数。长度和摘要都一致时直接使用 `at`，不做任何搜索（最常见的情况）。
- **不写 ID**：条目在内存中临时编号，写出时不保存，文件里只有位置和原文。
- **`review`**：重定位失败的条目原样保留在这里，附 `reason`，界面里可逐条应用到选区或删除。**任何情况下都不静默丢弃格式。**
- **每条一行**：条目按位置排序，写出时每条单独一行，Git 合并时冲突落在具体条目上。
- **上限**：每个 TXT 最多 50 000 条；`.vela` 中配置部分（不含格式记录）仍不超过 256 KB，整个文件不超过 8 MiB。

体积：44 万字、459 处粗体的长篇，0.9.7 旁注约 220 KB（58% 是整篇逐行摘要，每条格式约 196 字节），0.9.8 记录约 35 KB。

**0.9.7 旁注**（`正文.txt.vela`，`kind: "document"`，按全文偏移、含整篇逐行摘要）仍可读取：打开 TXT 时照常显示格式，下次保存时并入作品 `.vela`，旁注移入回收站（可恢复）。直接打开旧旁注只显示摘要。

### 3.3 第一版支持的格式（封闭集合）

| 类别 | 类型 |
| --- | --- |
| 行内 `marks` | `strong` 粗体、`em` 斜体、`underline`、`strike`、`emphasis` 着重号、`ruby` 注音、`size`（小/大两档）、`style`（行内命名样式） |
| 段落 `blocks` | `align`（居中/右对齐）、`indent`（无缩进）、`style`（命名样式） |
| 插入 `inserts` | `image` 插图、`csv-table` 关联 CSV/TSV 表格、`break` 场景分隔符 |

不做：任意字体、任意颜色、单元格公式计算、嵌套列表。这些需求更适合 Markdown 或导出后的排版工具。标题仍由章节规则识别，不作为格式保存。

## 4. 编辑器实现要点

- **显示**：一个 CodeMirror `StateField` 保存格式的 `RangeSet`：
  - 行内格式用 `Decoration.mark`。
  - 段落格式用 `Decoration.line`。
  - 插图和分隔符用块级 `Decoration.widget`。
  - 注音用行内 widget，显示在字的上方或后面。
- **随文字移动**：输入、删除、查找替换、章节操作都会产生 changes，`RangeSet.map` 自动映射。行内格式的边界规则与常见文字处理软件一致：在粗体末尾继续输入仍是粗体，在开头输入不是。
- **撤销**：加、去格式用 `StateEffect`，配合 `@codemirror/commands` 的 `invertedEffects`，与文字修改在同一条撤销历史里。
- **入口**：工具栏格式按钮，`Ctrl+B` / `Ctrl+I`，选区菜单的“格式”子项（`selection-menu.mjs` 已有 `extraItems`），以及命令面板。
- **复制粘贴**：文舟内复制时，剪贴板同时写纯文本和带格式的内部数据，粘贴回文舟时恢复格式。粘贴到外部只是纯文本。网页或 Word 的 HTML 粘贴可选转换粗体、斜体。
- **性能**：RangeSet 是平衡树，十万字正文加上万条格式没有压力。只渲染视口内的装饰。

## 5. 保存、同步与外部修改

- **保存顺序**：TXT 与旁注在同一次保存中写出，旁注里带上新的 `hash`。如果中途崩溃只写了 TXT，下次打开摘要不一致，会走重定位而不是用错误的偏移。
- **基线**：旁注自带每行摘要和行长，外部改稿后先**按行对齐**（相同的首尾行，加上两边都只出现一次、顺序不变的行），把没改的行上的条目直接映射过去；改过的行再在“该行在新正文中应处的区域”里按引文查找，最后才全文查找（实验中的策略 C）。这样换设备、经 Git 拉取后也能用，不依赖本机私有数据。
- **Git / Gitee**：TXT 与旁注作为两个普通文件提交。拉取时，如果正文变了而旁注没变，打开时自动重定位并标记“旁注需要保存”。旁注本身冲突时，按条目 ID 合并，两边都保留，再整体重定位。
- **文件操作**：重命名、移动、复制、删除到回收站、恢复、导入导出、工作区备份、本地历史恢复，都要把 `X.txt` 与 `X.txt.vela` 当作一组处理。文件侧栏默认隐藏旁注文件，在“显示配置文件”时才列出。`rewriteVelaFiles` 已有同类的路径改写，可以扩展。

## 6. 阅读、导出与插件

- **阅读页**：TXT 渲染时把格式转为 span 或块元素。注意：阅读位置、书签和分页依赖 `textContent` 偏移（`reading-position.mjs` 的 `textPoint`），所以注音和插图**不能**产生文本节点：
  - 注音用 `data-ruby` 加 CSS `::before` 绘制。
  - 插图用不含文字的块元素。

  分页测量需要把插图高度计入。
- **导出**：
  - TXT 和“导出章节文本”保持纯文本，不受影响。
  - 新增“带格式导出”：Markdown（能表达的部分）、HTML。
  - 将来的 EPUB 导出直接使用同一份格式，这与此前建议迁移的 EPUB 生成模块正好衔接。
- **插件接口 4**：之后可增加 `vela.documents.marks(id)` 的读写，以及格式变化事件，供插件做排版检查或平台适配。

## 7. 风险与实验

### 7.1 外部修改后的重定位（主要风险）

实验脚本：`node tests/vela3-anchor-experiment.mjs`。

- 素材：用小说常见词组生成约 2.5 万字、12 章正文（重复率高，是不利情况）。
- 标记：随机放 548 个，60% 为 1–4 个字的短标记。
- 计分：不统计被改动直接覆盖的标记，只看其余标记是否回到正确位置。

| 场景 | A 现有 `resolveAnchor` | B 引文 + 前后文 | C 按行差异 + B |
| --- | --- | --- | --- |
| 开头插入三段 | 418 / 123 / **7** | 545 / 3 / 0 | **548** / 0 / 0 |
| 删除中间一段 | 475 / 68 / **1** | 542 / 2 / 0 | **544** / 0 / 0 |
| 散落改错字 30 处 | 546 / 0 / 0 | 543 / 2 / **1** | 545 / 0 / **1** |
| 每段末尾加一句 | 232 / 313 / **3** | 540 / 8 / 0 | 541 / 7 / 0 |
| 全文改为 CRLF | 232 / 316 / 0 | 540 / 8 / 0 | 541 / 7 / 0 |
| 第三章整章移到末尾 | 397 / 95 / **3** | 493 / 2 / 0 | **495** / 0 / 0 |

格式：正确 / 待确认 / 错位。

结论：

1. 现有书签和批注使用的策略 A **会放错位置**，不适合用于格式。顺带说明：外部改稿后，现有批注也可能错位，值得一并改用新策略。
2. 有基线时，策略 C 在常见改稿方式下几乎完全正确。错位仍可能发生在短标记的同字重复处。对策：
   - 不足 2 字且前后文得分不高的条目一律进“待确认”。
   - 自动移动过的条目在界面上标出，可一键查看。
3. CRLF 场景中的“待确认”来自偏移基准不一致。按 3.2 的规定先统一为 LF 后，这一项与“无修改”相同。

### 7.2 其他风险

| 风险 | 对策 |
| --- | --- |
| 两个文件不同步（只复制了 TXT） | 旁注缺失时正文照常打开，不报错；旁注孤立时在文件侧栏提示，可关联或删除 |
| 文件操作遗漏旁注 | 集中写一个 `companionPaths(path)`，所有文件操作都经过它，并对每种操作写浏览器测试 |
| 其他工具不认识旁注 | 这是设计取舍：外部看到的就是纯文本。格式规范公开在本文档，偏移规则明确 |
| 富文本让编辑器变慢 | 装饰只在视口内渲染；未开启 `richText` 的作品不加载这部分代码路径 |
| 用户期望“所见即所得” | 格式在文舟的编辑器和阅读页可见；平台发布仍用纯文本，与网文实际流程一致 |

## 8. 分阶段计划

| 阶段 | 内容 | 验证 |
| --- | --- | --- |
| P0 | 第三版解析器（接受 2/3，按需升级）、`document` 旁注读写、重定位模块（策略 C）、基线保存 | 单元测试，包括本文实验转为断言 |
| P1 | 编辑器格式层：StateField、工具栏、快捷键、撤销、保存与加载、待确认面板 | 浏览器测试：编辑、撤销、保存重开、外部改稿后打开 |
| P2 | 文件操作长尾：重命名、移动、复制、回收站、历史、备份恢复、Git 同步 | 每种操作一个浏览器测试 |
| P3 | 阅读页渲染（注音、插图、命名样式）与分页 | 阅读位置和书签在有格式时不偏移 |
| P4 | 带格式导出（Markdown、HTML），之后接 EPUB 导出；插件接口 | 导出内容快照测试 |

建议先做 P0 与 P1 的最小闭环，并设开关：只支持粗体、着重号、居中，验证编辑手感和外部改稿体验后再扩展格式种类。

## 9. 实现进度

已实现（P0、P1 最小闭环；P2 中的重命名、移动、复制、回收站；P3、P4 中对应已支持格式的部分）：

- `web/rich-text.mjs`：旁注解析、写出（每条一行）、按行对齐与引文重定位。未知字段和未知条目类型原样保留、照常重定位，只是不显示。
- `web/rich-text-editor.mjs`：CodeMirror 格式层。行内格式在末尾继续输入时延续、在开头输入时不延续；段落格式随行移动，删除整行或退格并入上一行时随之去掉。格式命令和“删字带走的格式”都进入撤销历史。
- `web/vela.mjs` / `web/vela-v2.mjs`：接受 `version: 2` 和 `3`；`richText` 需要第三版；`kind: document` 交给旁注解析，体积上限 4 MiB。
- 界面：TXT 的格式工具栏（粗体 `Ctrl+B`、着重号 `Ctrl+Shift+E`、居中 `Ctrl+Alt+E`、待确认），“格式待确认”对话框（应用到选区或删除）。命令面板可开关“TXT 格式工具（本机）”；作品配置写 `richText.enabled: true` 也会开启；已有旁注的 TXT 总是显示格式和工具栏。文件列表不单独列出有对应 TXT 的旁注；直接打开旁注只显示摘要。
- 文件操作：重命名、移动、复制、移入回收站时，旁注在 JS 层随 TXT 再做一次相同操作，三端一致；恢复或永久删除 TXT 时一并处理它的旁注。

已知限制：

- 回收站里 TXT 与旁注是两条记录（恢复 TXT 时会自动恢复旁注）。
- 旁注在别处被改（同步拉取、手动编辑源码）后，打开中的 TXT 会在下次保存时重新载入旁注，而不是覆盖它；这次重新载入不进入撤销历史。
- 搜索结果和插件接口尚未使用格式。
- 插图只在原生应用中显示和导出（通过 `readWorkspaceAsset` 读取工作区图片）；浏览器预览显示占位框，导出时省略并提示。

- 阅读页（P3）：`renderPlainChapters` 按旁注把行内格式渲染为 span、把对齐行渲染为块级 span，行尾换行包在块内，`textContent` 与正文完全一致，阅读位置、书签、搜索偏移不受影响；长篇分块显示和分页测量使用同一渲染，偏移按区块起点换算。
- 导出（P4）：`web/rich-text-export.mjs`。“导出章节”对话框可选 TXT、Markdown、HTML。Markdown 每个非空行一段、章节标题为 `##`；粗体为 `**`，着重号为斜体，紧挨中文标点时改用 `<strong>`、`<em>`（CommonMark 的分隔符规则在中文标点旁失效），正文里的 Markdown 字符会转义；Markdown 无法表示居中。HTML 是不含脚本和外部资源的单文件，保留全部格式；复制 HTML 时剪贴板同时放入带格式内容和纯文本，可粘贴到支持富文本的编辑器（原生端暂只复制纯文本）。命令面板另有“导出全书为 HTML（保留格式）”。
- EPUB 导出：`web/epub-export.mjs`。命令面板“导出 EPUB…”或“导出章节”中的“导出 EPUB…”。EPUB 3 结构（`mimetype` 不压缩且在首位、OCF 容器、package、nav），另附 NCX 目录供只认 EPUB 2 的阅读器使用；每章一个 XHTML，保留粗体、着重号（`em.emphasis` 加 `text-emphasis`，含 `-epub-` 前缀）和居中。书名、作者、简介取自作品配置，可在对话框修改；可选封面（JPEG、PNG、GIF、WebP，≤5 MB）同时写入 EPUB 3 的 `cover-image` 和 EPUB 2 的 `<meta name="cover">`。书籍标识 `urn:uuid:` 按文稿保存在本机工作区数据中，重复导出时阅读器会认作同一本书。XML 不允许的控制字符在导出时去掉。2026-10-15 用 W3C EPUBCheck 5.4.0（EPUB 3.4 规则）校验了 4 种导出：带封面与全部格式、不含章节标题、章节范围加繁体语言代码、3000 段 11 章长篇。结果均为 0 错误、0 警告。尚未在实体阅读器上验收。
- 注音：`marks` 中 `type: "ruby"`、`value` 为读音（最多 64 字符）。编辑器和阅读页用伪元素把读音画在字的上方，不产生文本节点；在注音末尾继续输入不会扩大注音范围。导出 HTML、EPUB 为 `<ruby>…<rp>（</rp><rt>…</rt><rp>）</rp></ruby>`，Markdown 为内联 `<ruby>`。
- 插图：`inserts` 中 `type: "image"`、`src` 为相对本 TXT 所在文件夹的工作区路径（PNG、JPEG、GIF、WebP），可带 `alt`。插图挂在段落末尾：在段末输入或回车，插图都留在原段落之后。编辑器显示为块级图片，点击可编辑或删除；阅读页是不含文字、高度固定的块（分页测量与图片是否加载完无关）。原生端可从本机导入图片到 `插图/`。导出时 Markdown 写成 `![说明](路径)`，HTML 内嵌为 data URL，EPUB 每张图只打包一次并登记到 manifest。
- 命名样式：作品或全局配置的 `styles`（需要 `version: 3`），属性限定为对齐、缩进、字体、字号、颜色、加粗、边框，见 `web/rich-text-styles.mjs`。内置“系统提示”“书信”“回忆”（段落）和“旁注”（行内），配置可按 ID 覆盖或新增，最多 32 个。段落样式是 `blocks` 中的 `type: "style"`，行内样式是 `marks` 中的 `type: "style"`，`value` 为样式 ID；同一段文字只能有一个行内样式。“管理样式…”写入作品 `.vela`，没有作品配置时写入 `.global.vela`。编辑器和阅读页使用配色变量，导出使用适合白底和电子书的固定颜色，生成 `.style-<id>` 样式表；Markdown 不输出样式。

测试：`tests/rich-text.test.mjs`（旁注与重定位，包括第 7 节实验的回归断言：随机改稿下不得错位）、`tests/rich-text-editor.test.mjs`（格式层映射与撤销）、`tests/rich-text-export.test.mjs`（Markdown 与 HTML 导出）、`tests/rich-text-formats.test.mjs` 与 `tests/rich-text-formats-browser.mjs`（注音、样式、插图在旁注、编辑器、阅读页和三种导出中的表现）、`tests/epub-export.test.mjs` 与 `tests/epub-export-browser.mjs`（EPUB 结构、元数据、格式、封面、XML 良构、标识稳定）、`tests/rich-text-browser.mjs`（工具栏、快捷键、保存重开、阅读页与长篇分块、HTML/Markdown 导出与复制、外部改稿与待确认、重命名、回收站、旁注摘要）。

## 10. 0.9.8：格式并入作品 `.vela`，命名样式可用于文字

- **一个文件**：格式记录（`richText.documents`）、命名样式（`richText.styles`）和开关（`richText.enabled`）都在作品 `.vela` 里；文件夹中不再出现 `正文.txt.vela`。`.vela` 编辑页分“作品配置”“TXT 格式”两页：后者列出每个 TXT 的格式数量、待确认数和缺失文件，可打开 TXT 或移除失效记录，并显示全部命名样式。
- **文件操作**：重命名或在作品内移动 TXT 时改记录的键；移到另一个作品时记录随之移过去，目标没有 `.vela` 时新建；复制 TXT 时复制记录；移入回收站时保留记录，恢复后格式即回来。`.vela` 的配置备份不含格式记录，恢复备份时保留当前格式。
- **重定位**（`resolveRecord`）：先按行摘要找回没改的行；被改过的行，若它与前后找回的行之间行数不变，就在原行号上找原文（本行唯一，或前后文明显更好）；否则只在前后两行之间搜索，并且只接受无歧义的结果；其余进入待确认。第 7 节的实验（12 章、600 处格式、5 种改稿）在新格式下同样 0 处错位，每种改稿至少 95% 自动归位。
- **命名样式不再区分段落和行内**：任何样式都可用于整段或选中的字。选中文字时只作用于这些字，对齐和缩进不生效，边框画在文字外；没有选中时作用于光标所在段落。`block` 只决定样式面板默认的作用范围，并让 0.9.7 能读取带对齐、缩进或边框的样式。导出时段落用 `.style-<id>`，文字用 `span.style-<id>`。
- **格式工具栏**：粗体、着重号、注音｜居中、右对齐｜样式、插图｜清除格式、待确认，全部直接显示；“样式”按钮显示光标处的样式名，点开后是样式面板（选中文字 / 整段、全部样式的样例、清除样式、管理样式）。宽屏为按钮下方的弹出面板，窄屏和触屏为底部面板，按钮高度不小于 44 px。触屏上工具栏按钮为 36 px，放不下时横向滚动。选中文字后的菜单不再重复工具栏已有的格式命令（TXT 和 Markdown）。
- **清除格式**：去掉选区内的全部行内格式（粗体、着重号、注音、样式），以及所涉各段的对齐和段落样式；没有选区时只清除光标所在段落。插图不受影响。可撤销。

## 11. 关联 CSV / TSV 表格

`csv-table` 是 `inserts` 中的段落插入类型，字段为 `src`、可选 `caption` 与 `header`。源文件独立保存，TXT 正文不变。CSV / TSV 编辑页使用虚拟画布网格，阅读页使用只读滚动网格，均按源码位置局部写入；TXT 内嵌预览仍使用 Shadow DOM 静态 HTML，避免表格文字影响正文偏移。HTML、Markdown、EPUB 导出静态快照。路径保护、移动/复制规则及使用说明见 [CSV-TABLES.md](CSV-TABLES.md)、[ADR 0007](adr/0007-linked-csv-tables.md) 和 [ADR 0008](adr/0008-csv-grid-redesign.md)。
