# 仓库同步

文舟先在本地保存文稿，由用户主动拉取或提交到 GitHub、Gitee、Gitea。
仓库、服务器、分支和目录会显示在同步预览中，确认预览后才应用变更。

## 拉取与远端删除

完整拉取仓库时，文舟保留完整远端路径清单，用上次成功跟踪的文件核对远端删除项。
本地独有文件不会被当成冗余文件；局部拉取、仅拉取阅读清单、缺少完整快照或分支不一致时不推断删除。
带提交目录前缀的旧关联暂不推断删除，避免混淆仓库路径与本地路径。

拉取预览中，远端删除项默认不勾选。用户勾选后，确认未修改的文件才会移入已有回收站，支持恢复。
本地正文有修改、无法读取、归属其他分支或缺少可靠版本的文件会显示保留，不能通过同步删除。
确认删除前还会重新检查远端分支是否仍是预览中的版本；远端已变化时要求重新拉取。
附件在预览前与上次跟踪的 Git blob SHA 校验，确认写入时再次检查磁盘字节；正文也检查预览后的修改和磁盘文本。
文件夹不会随远端删除自动清理，因此空目录和本地独有内容会保留。

写入新文件与移入回收站使用一次本机同步操作。路径和版本校验失败会停止，操作异常时恢复已处理文件。
Windows、Android 沿用存储事务及日志恢复机制；HarmonyOS 使用暂存及异常回滚，先登记回收站位置再移动文件，
避免中断时已移动内容没有恢复入口。HarmonyOS 仍不承诺整个批次在进程突然终止时完全原子，后续需要补持久事务恢复验证。
回收站满时拒绝本次带删除的同步，不自动永久删除历史项目。

保留的远端删除文件会标记“远端已删除 · 本地保留”，工作区提交预览不会默认选中这些文件。
用户主动勾选重新上传，或对该文稿进行单文件提交时，会明确提示重新创建远端文件。
其他未勾选的远端更新会作为待处理项保留，阻止工作区提交直接覆盖它们。

## 分支与状态

远端文稿关联包含平台、服务器、仓库、分支和文件路径。
另一分支使用独立本地文件夹；打开另一分支的同名文件不会复用原文稿 ID 或覆盖本地修改。
如果文件夹已经属于另一仓库或分支，拉取写入会被拒绝。

切换分支前先保存到本机；当前分支有未同步的修改、新增、删除或冲突时，需要确认“保留本地变更并切换”。
取消后继续停留原分支；同步进行中禁止切换。新建分支后从列表主动选择，不自动改变浏览目标。

编辑页面不再显示常驻保存/同步状态行，以留出正文空间。自动保存、文稿标签的未保存标记及失败提示继续保留。
本地保存与最近同步的版本分别记录，保存到本机不会自动提交远端。仓库页面和提交/拉取预览显示平台、服务器、仓库、分支与路径。
其他设备是否更新了仓库，需要刷新或拉取后确认。

## 重复下载与设置清理

完整拉取仍然读取最新分支和目录，但相同 Git blob 优先复用经过摘要校验的远端缓存，包括不同分支共有的内容。
缓存按平台、服务器和仓库隔离，不包含本地修改、令牌和同步基线。最多保存 256 项、32 MiB Base64 数据，超过上限淘汰旧项。
支持 IndexedDB 时重启页面仍可复用；存储不可用时使用内存。拉取进度分别显示复用和实际下载数量。

设置 → 工作区配置 → **清除冗余文件**，可单独清理下载缓存，或选择当前已登录平台的已关联仓库和分支，先扫描再预览旧文件。
扫描只读取完整远端目录，不下载正文或附件。远端已删除且本地确认未修改的已跟踪文件可勾选移入回收站；本地独有、已修改、无法校验的文件保留。
带目录前缀的关联和空文件夹暂不自动清理。清理不会推进未拉取内容的提交基线，也不会清除原有待处理冲突。

## 验证

- 单元检查覆盖三个平台的删除识别、局部拉取边界、附件版本、分支隔离、保留文件提交状态。
- Windows 存储检查覆盖回收站恢复、原文稿 ID、预览后外部修改、重复路径、失败回滚。
- 浏览器检查使用实际预览模块，覆盖默认不选删除、修改文件禁选、预览失效和分支冲突。
- `node tests/sync-safety-windows.mjs` 在隔离数据目录使用生产 UI、原生桥和真实文件系统走完整拉取/删除/恢复流程；远端接口为测试替身，不使用线上仓库。
- Android 原生测试加入同步删除及恢复检查；构建通过不能替代设备运行验证。
- `tests/sync-workflow.test.mjs` 检查分支确认、缓存版本/范围/淘汰、只读目录扫描及清理基线保护。
- `tests/sync-workflow-browser.mjs` 检查缓存跨重载复用、设置清除、移除常驻状态行及本地修改保留。

这些检查随 `npm run verify` 运行；Windows 原生界面检查使用 `npm run verify -- --windows`。
