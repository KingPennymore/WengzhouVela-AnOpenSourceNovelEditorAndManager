# 0.9.5 基础上的布局、模板、VODT 和选区菜单改进

后续修订：ODF 已改为可选组件，当前使用方法与支持范围以 [ODF-COMPONENT.md](ODF-COMPONENT.md) 为准；本文保留早期原型说明/验证记录。

本次为源码更新与实验性富文本原型，保持原项目版本号 0.9.5；不是三端已签名安装包。

## 布局

- 固定网页根容器，禁止 html/body 滚动；正文、阅读区、文件列表等保留各自的滚动。
- 顶底栏不随拖拽移动；顶部仍由原生系统避让区和已有安全边距确定。鸿蒙默认窗口非全屏，顶部已由 ArkUI 避让，不重复添加状态栏高度。
- 软键盘缩短可用高度时，底栏移动到键盘上方；不跟随 visualViewport.offsetTop 发生页面平移，也不重复扣除原生已缩小的高度。

## 文件模板

新建文件根据扩展名过滤模板，不自动改变用户填写的文件名。

| 格式 | 模板 |
| --- | --- |
| TXT、Markdown、.velaodt、.vodt、FODT | 空白、小说正文、故事大纲、人物设定、世界观设定 |
| CSV、TSV | 空白、章节规划表 |
| HTML | 空白、离线阅读页 |
| LaTeX | 空白、ctexart 中文文稿 |
| GLY、GLossary | 结构正确的空术语库 |
| VELA | 结构正确的工作区配置 |
| 常见代码 | 空白，避免加入不相关的小说内容 |

## .velaodt 与 .vodt

两者是同一格式的扩展名别名，读写与编辑行为相同；仅重命名后缀即可互换。不是把 ZIP 二进制当作文本。

采用 ODF 1.3 扁平 XML（FODT 路线），以 UTF-8 保存，正文位于 office:body/office:text。现有三端文本文件保存、Git 提交、历史恢复机制可以继续使用。图片嵌入 office:binary-data，导出 ODT 时转成 ZIP 中的 Pictures 文件并写入清单。程序可以提取纯文本，编辑器也提供 TXT 导出；直接用文本编辑器打开文件会看到 XML 标记和图片 Base64。

界面默认打开富文本，保留“源码”切换。手机顶部格式工具横向滚动；正文独立滚动；底部保存、撤回等仍使用原有栏位。源 XML 会随富文本编辑更新，保存后重开可恢复格式与图片。

### 当前支持

- 段落、标题、粗体、斜体、下划线、删除线、字号。
- 左对齐、居中、两端对齐、首行缩进。
- 无序列表、基础表格；安全链接结构的读取和保存。
- 本地 PNG/JPEG/GIF/WebP 插入；WebP 转 PNG 以改善办公软件兼容。
- 点击图片后调整显示宽度、保留比例、修改图片说明、删除图片。
- 图片保存、重开、ODT 导出及带图片 ODT 回读。
- TXT、FODT、ODT 导出；普通文字和支持的图片 ODT 转换导入。
- 阅读页可显示 VODT 文稿和内嵌图片。

图片不访问外部 URL。单张最多 2 MiB；静态大图片缩至最长边 1600 px，GIF 原样保存；显示尺寸不等同于原始像素。整份扁平文件仍受项目原有 8 MiB 限制；ODT 输入最多 8 MiB，解压内容最多 32 MiB、最多 1024 条目。转换后若超过 8 MiB 会拒绝导入。Base64 对图片原始字节通常增加约三分之一体积；导出 ODT 可消除这项编码膨胀，因此包含多图的文档更适合用 ODT 交换。

### 兼容性与边界

- 外部 FODT/ODT 采用兼容阅读模式，保留正文、样式及支持的图片。可在工具栏“创建可编辑副本”，将当前可显示的内容转换为支持的简化结构；此操作新建副本。
- 导入文档不是逐像素复刻。复杂样式继承、编号列表、合并单元格、页眉页脚、分栏、浮动图文、公式、脚注、批注、修订、嵌入对象、精确打印分页均未实现完整编辑。
- 不支持的嵌入对象、内嵌字体、签名以及外部/缺失图片会使 ODT 转换被拒绝，不覆盖原始文件。包含复杂结构的 FODT 可读取源码，但预览可能不显示全部内容。
- 不能承诺任意办公文档无损编辑。当前目标是小说/设定文稿的常用图文编辑与标准格式交换。
- 富文本原型使用 Chromium 的 contenteditable 和编辑命令，没有引入办公引擎。大文档目前会重新序列化 XML，后续应加入增量模型和更细的撤回记录；不宣称完整办公编辑器已经完成。

### 最小体积路线

复用现有 fflate、浏览器 XML 解析和图像解码，不新增运行依赖，不内置字体。基础段落、标题、内联样式、列表、简单表格和内嵌图片适合这一方案。若要可靠地实现精确分页、复杂图文环绕、完整 ODF 样式继承和多种办公软件相同的版面，还需要排版引擎与更完整的文档模型；不应使用一个未经验证的固定体积估计。

## 竖向文字选区菜单

- 复制、粘贴、剪切、搜索、加入词库、关闭；只读内容隐藏粘贴和剪切。
- Markdown 追加加粗、斜体、引用；LaTeX 追加加粗和行内公式；富文本追加加粗、斜体和下划线。
- 普通设置输入框只显示适合输入框的复制/剪切/粘贴，不给密码输入框添加文字操作。
- 优先放在选区上/下/左/右的空位。无可用空位时，在屏幕底部创建可滚动的竖向菜单区域并缩小正文所在容器，选中内容不会被菜单覆盖。安全区也计入预留高度。
- 超出 CodeMirror 当前渲染范围的长选区使用可见边界计算。
- 调整选区手柄期间隐藏菜单，结束后更新；关闭菜单会恢复正常可用高度。
- 搜索使用当前文稿查找，阅读模式使用已有阅读搜索；词条沿用现有术语库关联流程。
- Android 保留系统 ActionMode/选区手柄的生命周期并移除横向项目；鸿蒙通过 editMenuOptions 移除系统项目，网页显示共同菜单；Windows 处理右键/选区事件。
- 三端剪贴板使用原生桥接。鸿蒙只在点击粘贴时申请 READ_PASTEBOARD；拒绝授权不会剪切或改变选区。发布时需按鸿蒙受限权限规范配置权限能力。
- 不接管其他软件的全局菜单；隔离的 HTML 预览窗口/iframe 有独立原生环境，不在本次网页菜单的作用域中。
