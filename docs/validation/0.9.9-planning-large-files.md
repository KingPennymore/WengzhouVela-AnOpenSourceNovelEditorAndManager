# 0.9.9 大型 PCS / VLMP 多标签测量

测试基于 master `36a03e6`、已有侧栏 / 标签优化 `2b1382f`，加本次首次居中和锚点查询缓存改动。环境为 Linux Headless Chromium 153，1280×850；窄屏为 390×850。CPU 4 倍降速与窄屏均为桌面仿真，不能作为 Android / HarmonyOS 真机结果。

## 可复现方法

```sh
npm ci
WENZHOU_CHROME=/path/to/chrome npm run test:planning:stress
```

可用 `VELA_PLANNING_CASE=heavy-10-desktop` 单独选择场景，用 `VELA_PLANNING_OUTPUT=...json` 指定输出。默认结果为 `test-results/planning/multitab-performance.json`。计时基准单独运行，不与其他 CPU 密集任务并行。

交付补丁只包含源码与验证记录；集成后需重新执行前端构建，再打包目标平台，才能在应用里使用本次改动。

每组准备三个或五个 PCS / VLMP 对，交替激活全部标签，循环三轮。每个 PCS 节点含标题、摘要、Markdown 详情和少量额外连线；关系图场景为每图 1000 节点、4000 关系边。每张 VLMP 除绘制点外，含 250 信息点、200 符号、100 箭头，并开启参考网格。第一张地图未预存填充边界，以覆盖首次生成；其余地图有预存填充。

工作区文件文本在开始时已经载入。首次激活包含视图构建、地图首次填充计算等工作，不包含磁盘读入。大型工作区超过浏览器 localStorage 配额，因此只将工作区存储键替换成内存实现；应用自身 JSON 序列化、验证仍会执行，真实磁盘写入和原生桥接耗时未测。

“切换完成”取点击开始至对应图形 DOM 出现并经过两次 requestAnimationFrame 的时间；这是端到端页面完成指标，不是单纯 Canvas 绘制耗时或真实屏幕呈现时间。重复切换统计第二、三轮；每种类型只有 6 或 10 个重复样本，P95 会接近最大值。本次为合成数据单次矩阵测量，不宣称跨设备精确表现。

## 结论与实现边界

文件文本保留在工作区内存中，但“标签已打开”不等于整张图形视图常驻。PCS 解析对象和地图会话有缓存；每次进入仍构建图形界面。编辑器状态最多保留八个，十个规划文件循环切换会超出缓存容量。关闭标签也不会从工作区删除文件文本，所以关闭后 JS 堆不会归零。

PCS 的节点卡片、摘要 Markdown、连线 SVG 目前全部生成，尚未按视口虚拟化。VLMP 每次进入仍解析和验证文件；首次没有填充边界的地图还会计算填充。切换时也会设置隐藏的源码编辑器状态。这些都是代码路径检查发现的开销来源，尚未通过逐函数 CPU 分析分摊耗时，不能把整段延迟归因于其中某一个函数。

本次将正文边栏锚点查询从每个可见行一次，改为每个编辑器状态一次。编辑、切换状态和显式锚点变更事务都会失效；WeakMap 不增加对编辑器视图的永久引用。浏览器回归直接验证查询次数及失效后的标记更新。该改动削减重复扫描，但压力测试仍有明显切换延迟，不能据此宣称大型文件已流畅。

侧栏动画自身能进入并完成过渡，后台保存会等待过渡结束；但主线程长任务仍可能使动画掉帧。尤其地图缩放到全图后，同屏绘制更多点和符号，不能用普通缩放下的低绘制耗时推断全图同样流畅。离开地图后会取消画布帧任务，空闲期间没有持续绘制。测试未启动地图整理算法的 Worker，不能据此判断所有后台算法的耗时。

内存通过 CDP 强制 GC 后读取 JS 堆，另记录 DOM 节点数；数值包含内存存储替身和测试采集器，不能直接作为产品的绝对内存预算。三轮稳定仅表示本次循环没有观察到明显持续增长，不足以排除其他操作路径泄漏；不包含 GPU、图片解码、原生层或进程总内存。

## 首次打开自动居中

首次进入 PCS 大纲 / 关系图或 VLMP，会按实际内容边界居中并缩放到可见区域，保留边距；首次不放大超过 1 倍。空地图将原点放在画布中心。再次进入同一标签保留手动平移、缩放，正文锚点的定向跳转继续优先定位目标节点。

地图边界现在包含生成的填充区域，并避免把无内容的世界原点纳入远处图形的边界。对极稀疏、距离极远的点，缩小全图时改为遍历已有点，避免扫描巨大的空坐标矩形。极小缩放下的手势也不会突然跳回原来的最小缩放。

`planning-centering-browser` 覆盖 1280 / 390 px 的大纲、关系图、远离原点地图、填充区域、空地图与跨标签视口恢复；`planning-viewport.test.mjs` 覆盖边界和极稀疏地图。首次适应操作仅在初始化或用户点击“适应全图”时计算，普通平移帧不重复扫描边界。

## 回归结果

353 个单元测试通过。六组浏览器检查通过：`outline-marker-cache-browser`、`planning-centering-browser`、`planning-browser`、`planning-feedback-browser`、`animation-blocking-browser`、`map-performance-browser`。另外六组多文件压力场景全部完成且无页面错误；轻量构建与 `scripts/check-build.mjs` 均通过。普通缩放下独立的 20000 点绘制基准 P95 为 3.40 ms。

现有 `map-interaction-browser` 未通过：两指变换后的元素 x 位移断言失败。单独检出改动前的 `2b1382f`，使用同一 Chromium 也复现同一断言失败，因此该项记录为既有失败，不计入本次通过数。Android / HarmonyOS / Windows 原生程序和真实文件 IO 没有在本环境验收。
