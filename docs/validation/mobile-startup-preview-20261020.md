# 移动端抽屉与启动体验试用验证（2026-10-20）

本次提供 Android 轻量试用 APK，使用既有发布证书，包名与当前版本一致。没有发布远端更新、增加 AAB 或改变模块加载策略。版本基于 0.9.9.4-android.1，试用文件名另带 startup-preview-20261020。

## 实现

- 手机左右抽屉使用独立、无单位的展开进度，保留编辑区域宽度；打开、关闭、连续切换均保持动画，减少动态效果时直接切换。
- 选择侧栏内容时，浮层菜单属于侧栏操作，选中后保留当前抽屉。
- 信息点图标选择支持触屏、滚动、主动搜索及键盘弹出后的重新定位。首次打开不主动唤起软键盘；系统返回先关闭选项菜单。
- 窄屏（≤600 px）启动不再自动展开文件侧栏；只有桌面宽度才沿用上次的侧栏展开状态。
- 页面入口前的小脚本只读外观缓存，恢复深浅模式和配色（含自定义色值），跟随系统时优先使用宿主外观。中心文舟图标先出现；顶栏、标签栏、底部快捷栏、状态栏与已展开的侧栏以 30–40ms 阶梯、180ms 时长依次滑入；主栏接近落位时图标先快速起跳、顶点减速、下落加速、落地轻压后淡出（320ms，上跳 32px），正文随后以 240ms 淡入上浮，开屏底色用 260ms 渐隐。应用初始化与图标展示重叠，启动节奏按固定 240ms 的落位点放行，不等待慢插件。
- 启动失败或入口加载失败会释放遮罩和不可交互状态；支持减少动态效果。
- 侧栏布局尺寸集中读取并缓存，仅几何发生变化时重新测量编辑器；列表进入动画把逐项强制布局合并为一次，启动时由整体布局动画接管。
- 保留启动迁移的同步落盘保障；后台保存尚在进行时，离开页面等生命周期事件也触发最终保存保护。

## 验证

新增 `tests/mobile-startup-regressions-browser.mjs`，注册到统一验证脚本。使用 390px、320px 的触屏浏览器上下文验证缓存外观、分阶段启动、真实逐帧抽屉进度、重复切换侧栏、信息点图标搜索、模拟键盘视口变化、返回层级、保存与重启；另测减少动态效果、首次启动、宿主系统深色及错误恢复。`tests/startup-content-browser.mjs` 同时核对窄屏侧栏不自动展开、分段滑入延迟递增及正文在图标退场后才创建。

原有布局与原生选区测试改为等待 `velaReady`，再开始交互或读取最终布局；抽屉关闭断言等待实际退场完成，文档格式测试等待异步打开结束。

391 项单元测试通过。完整回归首轮发现的启动迁移、动画完成时机及测试就绪条件问题均已处理并复测。Windows 原生启动、名词候选 Worker、增量保存、阅读与隔离 HTML、轻量版导入 TeX 组件并实际编译 PDF 通过。具体记录保存在 `test-results/startup-first-verify/`、`test-results/startup-second-verify/`、最终 `test-results/verify/` 与 `test-results/windows-071-results.json`。

## 第一版试用性能样本（正文延后调整前）

同机 Chromium、390px、4 倍 CPU 降速，源码服务（未压缩），每组 3 次独立上下文取中位数，对照当前 HEAD 0.9.9.4。每份文稿约 2,000 字；“初始化”是 `vela:core-ready` 标记，“可交互”包含本次新增的布局进入及图标退出动画。该模拟不等同于 Android 真机测速。

| 文稿数 | 初始化：旧 → 新 | 可交互：旧 → 新 | 最长主线程任务：旧 → 新 |
| --- | --- | --- | --- |
| 1 | 1463 → 907 ms | 1464 → 1512 ms | 403 → 310 ms |
| 300 | 2239 → 1333 ms | 2239 → 2307 ms | 1008 → 504 ms |

初始化及单次阻塞明显减少；计入完整动画后，这组样本的可交互时间接近旧版，不能据此宣称真机启动总时长已有确定降幅。真机体验需由试用包确认。原始样本见 `test-results/mobile-startup/performance.json`。

## 第二版试用：只让正文等待 Logo 退场

最终反馈将等待范围缩小到正文：标签栏、格式工具栏、顶栏底栏和已打开的侧边栏在 Logo 期间正常展示，只有编辑器、预览正文和启动页主体在 Logo 退出后创建。侧栏文稿目录提前填充，正文容器在动画期间跳过布局和绘制；插件初始化在正文创建后开始。模式和配色在启动时直接应用，常规手动主题切换仍保留渐变。

`tests/startup-content-browser.mjs` 在 320px、390px、1280px 下分别测试文稿和启动页；暂停布局进入与 Logo 退出动画，检查两个阶段均未创建编辑器和启动页主体，文稿标签栏和侧边栏可正常绘制，并比较正文出现前后的顶栏及底栏尺寸。原有工作区重启检查改为等待启动完成后读取侧栏状态。

## 信息点与链接选择

- 类别改用应用内选择栏，移除原生 datalist。只有选择“其他”才显示自定义类别输入；切换到预设或已有类别时隐藏、禁用输入，保存时忽略其中残留值。未分类、已有自定义类别及旧信息点保持可用。
- 地图链接与 PCS 的术语库链接复用 `planning-link-picker.mjs`：文件选择、应用内菜单、确认、错误与加载状态共用。链接窗口以叠加方式打开在信息点表单上方，信息点详情保持可见、不收起；关闭或系统返回只关闭链接窗口并直接回到原表单，名称、类别、图标、备注等草稿保留；只有保存信息点才提交链接变化。
- 应用内菜单向上展开时按实际高度紧贴控件定位，搜索导致高度变化时重新定位，避免短列表按最大高度计算而错位。
- 新增 `tests/map-info-choices-browser.mjs`，在 320px、390px、844×390 横屏及 1280px 下验证类别选择、条件输入、多次修改图标后重开、短列表边界和锚点、地图与术语库共享外观、链接窗口叠加不收起详情、返回层级、草稿、链接保存与移除，以及旧术语库 ID 持久化。

第二版试用文件带 `r2` 后缀，第一版试用包保留。前面的性能样本针对第一版，不能用来代表正文拆分后的总启动时长。
