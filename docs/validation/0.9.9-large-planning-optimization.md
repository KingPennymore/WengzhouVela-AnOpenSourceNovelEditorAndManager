# 0.9.9 大型规划文件与六边形格线优化

基于上一轮 `4fcda06`，本轮修改图形渲染与切换路径。此前大文件测量见 [上一轮验证记录](0.9.9-planning-large-files.md)。所有计时均为本环境 Linux Headless Chromium 153；窄屏和 CPU 4 倍降速属于桌面仿真，未验收 Windows Electron、Android、HarmonyOS 真机。

## 实现

- 六边形格线：共享矩形周期纹理，用 CanvasPattern 按世界坐标平铺。普通平移复用纹理；主题、方向、屏幕尺寸档位和 DPR 变化时取新纹理。尺寸接近不可辨识范围时逐渐淡出，较大格子保留清晰的矢量路径回退。共享纹理缓存最多 12 项、8 MiB 像素数据，不是整个应用的内存上限。保持原来的图层顺序，纹理仍在地图画布内合成，没有增加多个全屏高 DPI 画布。
- 地图数据：先检查文档文本是否变化，再解析和验证；点坐标、格子边界与信息点共用几何缓存。全图范围按中心坐标极值加六边形外接范围计算，避免每个格子重复计算六个顶点。编辑、取消、撤销会使缓存失效；公开导出的范围计算默认重新计算，兼容调用方原地修改数据。
- 地图远景：按世界坐标建立最多四档稀疏点概览，平移复用；缩小时减少重叠的点和文字。原始点、标签和命中数据保留，放大后恢复细节，显示降级不修改文件；PNG / SVG 导出保留完整内容，PNG 不套用远景简化。
- 首次填充：超过 2000 点且没有保存填充的地图在 Worker 中计算和校验，先显示地图内容；离开页面终止任务，进入源码或快速切换时不留下后台工作。完成后仅更新预览，不自动写文件，也不覆盖手动平移、缩放。绘制点编辑提交后的边界更新仍沿用原有同步流程，本轮没有把所有编辑计算都迁到后台。
- 大纲：超过 200 节点或 500 显式关系时启用分级渲染。远景使用聚合概览，点击区域逐步放大；方向键选择节点、回车查看。近景只生成视口和缓冲区附近的卡片，中等缩放隐藏 Markdown 详情，进一步放大后按需渲染。位置、节点和关系数据仍完整保留。
- 连线：拖动只更新关联边的几何与已有 SVG 路径。大图数值模型按最近使用缓存，最多 12 项，并限制总计 20000 节点、50000 边；退出图形时释放观察器和绘制任务，缓存不持有隐藏 DOM。
- 源码编辑器：预览保留完整文本状态、撤销和插件扩展，延迟启用语法、行号、锚点标记和换行渲染。进入源码后恢复这些功能，切回预览或从其他标签返回图形时停用。没有把文档文本改成磁盘按需读取。
- 布局：相同插件顶栏按钮不再反复搬动并触发布局；侧栏尺寸读取集中到写入之前；图形画布使用布局与绘制隔离。上一轮 CPU 采样中，工具栏和侧栏的同步布局读取是明显热点，相关成本随全量节点 DOM 一同下降。

重复切换只统计第二、三轮，计时到新图形 DOM 出现及两次 requestAnimationFrame；它不是像素真正呈现时间。优化后的远景使用简化显示，不能解释为仍完整创建所有卡片而获得同样速度。首次地图填充完成时间单列，避免把延迟工作算作已经完成。

大工作区使用内存存储键绕过 localStorage 配额；应用自身 JSON 处理仍执行，磁盘与原生桥接未测。强制 GC 后的 JS 堆包含采集器与内存存储替身，不代表进程、GPU、原生层和纹理总内存。三轮稳定不能证明其他操作路径没有泄漏。

## 格线对照

`npm run test:grid:stress` 分别检查 1280×720、2560×1440、3840×2160，DPR 1/2，两种六边形朝向，缩放 1/0.4，共 24 组。同一浏览器比较旧版逐格生成路径和纹理方式。下表为 pointy 朝向、缩放 1 的格线 CPU 提交 P95，单位 ms：

| CSS 画布 | DPR | 原路径 | 纹理 |
| --- | ---: | ---: | ---: |
| 1280×720 | 1 | 3.2 | 0.1 |
| 1280×720 | 2 | 3.3 | 0.2 |
| 2560×1440 | 1 | 18.1 | 0.2 |
| 2560×1440 | 2 | 20.4 | 0.1 |
| 3840×2160 | 1 | 64.0 | 0.2 |
| 3840×2160 | 2 | 64.3 | 0.1 |

每组预热 2 帧、统计 8 帧，小样本 P95 接近最大值。以上不包含 GPU 完成、合成和实际刷新，不能据此宣称 4K 恒定 60 FPS。旧版在 2K / 4K 的部分缩小场景超过候选格上限而直接隐藏格线，这些场景不作为等量绘制速度对比。

两朝向 × 两 DPR 的 216 个边中点均与世界坐标对齐；80 次缩放档位变化后，共享缓存为 12 项、约 3.42 MiB。原始 JSON 为 `test-results/planning/hex-grid-performance.json`。

## 回归与复现

```sh
npm ci
TZ=UTC WENZHOU_CHROME=/path/to/chrome npm run build:lite
TZ=UTC WENZHOU_CHROME=/path/to/chrome npm run test:planning:stress
TZ=UTC WENZHOU_CHROME=/path/to/chrome npm run test:grid:stress
```

`TZ=UTC` 避免现有 ZIP 打包器把固定的 1980 年 UTC 时间转换到本地时区后判为 1979 年。补丁只含源码、测试和记录；应用打包前需重新构建。

356 个单元测试通过。构建与完整性检查通过。20 组针对性浏览器检查通过（含单独复测），覆盖：大图远近景、方向键、局部连线、编辑撤销、源码切换、地图解析复用、填充任务完成与取消、首次居中、普通规划操作、地图跳转、侧栏、横屏、主题、正文编辑和富文本。插件集成的 7 项 API、跨文件提交、生命周期、压缩包和卸载检查也通过。

地图跳转回归覆盖 32 张地图，前进 64 次、返回 64 次；两轮 GC 后 DOM 均为 2533，事件监听均为 306，JS 堆约 11.65 → 11.84 MiB，未观察到持续积累。

现有工作区套件的 GitHub 文件长按多选断言仍失败。在单独检出的 `4fcda06`、同一 Chromium 和源代码服务器上也复现相同失败，记录为既有问题，不计入通过数。此前记录的地图双指用例失败没有在本轮宣称已修复。
