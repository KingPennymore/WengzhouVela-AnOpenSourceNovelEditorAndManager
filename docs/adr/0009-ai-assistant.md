# 0009：AI 助手的密钥、请求通道与生成结果

状态：已采用。

## 背景

用户希望接入自己的 AI 服务，把章节整理成术语库、大纲与关系、地图，并在写作时获得续写建议。
文舟此前只在仓库同步、订阅和组件下载时联网，隐私政策承诺文稿不上传；接入 AI 会把正文发给第三方。
服务种类多（国际、国内、本机模型），请求格式不统一；编辑器又必须兼顾中文输入法、术语补全和 Tab 缩进。

## 决定

- 默认关闭。首次启用说明数据去向并由用户确认；整理文件每次发送前确认范围与字数，续写只发光标前设定范围的文字。
- 用四种请求格式（OpenAI 兼容、Anthropic、Gemini、Azure OpenAI）覆盖各类服务，预设只是默认地址和模型，可自定义地址。HTTPS 必需，本机与局域网地址允许 HTTP。
- API Key 与 Git 令牌一样只保存在原生层的系统安全存储，前端通过 `ai` 原生调用代发请求，拿不到明文。Key 绑定保存时的接口地址，原生层只放行所选格式的生成与模型列表路径。浏览器预览版仅供测试，Key 只在页面内存中。
- AI 输出只接受约定的 JSON，经过各文件格式现有校验，以草稿预览，用户确认后合并或新建，整体可撤销。地图只生成信息点，不推断地形。
- 续写建议是 CodeMirror 装饰，不进入文稿和撤销记录；输入法组合期间不显示；建议显示时 Tab 接受，否则仍为缩进；触屏通过点按建议和浮条接受或拒绝。
- AI 相关模块全部按需加载，不增加启动体积；第一版不做流式输出，不向插件开放。

## 结果

数据只在用户明确操作时离开设备，且直接发往用户选择的服务；隐私政策与应用市场申报需同步更新。
更换接口地址需要重新输入 Key，这是为了防止 Key 被发往未经确认的地址。
不支持流式输出意味着长批次要等整批完成；续写为短文本，影响有限。
三端原生层都要实现 `ai` 调用和密钥存储，后续新增请求格式时，前端适配与原生路径白名单需一起修改。

## 2026-10-29：生成草稿与编辑器扩展

- AI 面板只承担功能入口与状态，整理视图、请求分批、纯格式适配、事务落盘和续写扩展各自独立。整理模块在首次整理时加载，续写扩展在首次启用时加载；主程序仅提供有界的宿主接口和编辑器 Compartment。
- 不再增加第二套文件保存或 AI 专用同步协议。`ProjectService.bindBuiltin` 为可信应用功能建立私有事务会话，复用原有队列、编辑锁、文件修订、后端原子提交及恢复。这个入口不出现在插件 API 中，也不改变插件授权要求。AI 适配器只允许当前作品内由用户选择的目标；响应内容无法指定文件路径或 ID。
- 草稿合并前重新校验用户编辑的字段及目标预览基线，再用现有 `.gly` / `.pcs` / `.vlmp` 解析器生成规范文本。术语库与 `.vela` 的关联一次提交。整体撤销使用相反的同一类事务，先检查被修改文件的修订，避免覆盖后续编辑。
- 地图地点互链使用有界 `relatedIds`，与已有的跨地图文件 `link` 分开；既有地图可不提供此字段，现有路径校验和迁移规则不变。
- 续写使用独立 StateField / ViewPlugin，只有用户接受时才向正文提交普通可撤销编辑。输入法、补全与真实输入优先；过时请求在返回后仍检查文稿、光标、焦点和运行状态。请求通道统一核验启用与同意、绑定服务、取消和每日额度。
- 按模型配置的上下文上限保守分批，保留输出与指令余量；不把固定字符数宣称为精确 token 计数。更大的上下文必须由用户按所选模型配置。
