# 0006：同步流程、可丢弃缓存与清理边界

状态：已采用。

## 背景

本地保存成功并不能说明远端已更新；分支浏览目标与当前文稿的关联目标也可能不同。
完整拉取反复下载相同附件，设置中的冗余文件清理则需要避免把未同步文稿当成缓存。

## 决定

- `repository-navigation.mjs` 在分支切换前保存，列出当前关联分支的待同步变更，由用户选择保留并切换；同步中禁止切换，取消保持原目标。
- `repository-pull.mjs` 负责不可变提交快照和路径校验，适配器继续负责各平台 API。目录清单始终重新读取，扫描删除不下载文件内容。
- `sync-blob-cache.mjs` 只缓存远端 Base64 字节，以平台、服务器、仓库和 Git blob SHA 隔离，复用前校验 Git 对象摘要。缓存不参与冲突基线计算，不写凭据或本地修改。
- 缓存最多 256 项、32 MiB Base64 数据，内存和 IndexedDB 分别受限；存储不可用时退回内存。清理使此前请求失效，阻止旧响应重新填充。
- `sync-workflow.mjs` 协调预览、本地与远端复检、原生写入及关联元数据更新；`sync-commit.mjs` 管理提交计划和原始远端版本保护。
- `sync-cleanup.mjs` 复用正常同步的删除判断和回收站操作，只处理完整快照证明已从远端删除的已跟踪文件。清理扫描不推进提交基线，也不消除尚未处理的冲突。
- 本地保存与最近同步分别记录，目标显示在仓库页面和同步预览中。编辑页不显示常驻状态行，避免挤占正文；保存失败仍提示，文稿标签继续标记未保存内容。最近同步记录不自动宣称远端当前没有新提交。

## 结果

更换分支不重新绑定当前文稿；清理不触及本地独有文件、已修改正文和无法确认版本的附件，删除默认不选并可恢复。
空目录、其他平台未登录的关联、带目录前缀的关联暂不自动清理。缓存可以单独清除，代价只是下次重新下载。
新模块使用 JSDoc 说明边界并统一格式；同步行为通过单元测试、浏览器持久缓存与状态检查，以及 Windows 实际文件系统流程验证。
