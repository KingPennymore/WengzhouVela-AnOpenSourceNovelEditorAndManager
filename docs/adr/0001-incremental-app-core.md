# ADR 0001：渐进拆分应用核心

- 日期：2026-10-21
- 状态：已采纳

## 背景

`web/app.js` 同时承担视图装配、工作区启动、保存调度、快捷键和平台环境响应。
已有业务模块和跨平台存储协议仍然有效，但入口内的长行和共享变量使保存时机、启动顺序难以单独验证。

## 决定与原因

采用渐进抽取，入口继续装配业务和界面，每轮迁出一个可以独立测试的职责。
`web/app-core/` 为本轮边界：

- `workspace-startup.mjs`：恢复事务、读取和验证工作区、设置默认值、建立 DocumentService、初始化存储及指南迁移。
  文稿服务使用工作区 getter，因为项目提交会替换工作区对象。
- `workspace-session.mjs`：保存定时器、未保存状态、后台保存合并与退出保护。
  文稿修订和快照继续由 DocumentService 负责，存储读写继续由 platform.mjs 负责。
- `command-bus.mjs`：快捷键和命令面板共用命令入口；阅读页限制和按钮可用状态在执行时读取。
  现有按钮保留各自业务处理，后续可逐条迁成直接处理器。
- `shell-layout.mjs`：只移动已有 DOM 节点，保留按钮监听和插件挂载点；不缓存入口状态。
- `platform-environment.mjs`：接收原生环境事件、更新安全区及平台标记，再通知界面处理主题和侧栏。
  原生协议和平台能力仍集中在 platform.mjs。

启动顺序必须保持：恢复事务 → 读取并验证 → 文稿基线登记 → 存储采用与迁移 →
项目服务就绪 → 插件运行时及视图装配 → 启动遮罩就绪 → 展示正文 → 插件加载与账号读取。
读取失败进入恢复界面并禁止写回，不能用空工作区覆盖损坏数据。

普通保存继续等待侧栏动画结束；显式保存、离开页面和切换有修改的文稿继续同步确认保存。
后台保存采用单次在途请求，期间的再次请求合并成下一轮保存；修订是否已落盘由 DocumentService 判定。

## 类型与代码规范

保留 JavaScript，五个核心模块均用 JSDoc 和 `// @ts-check`，由 `jsconfig.core.json` 严格检查。
工作区启动模块声明自己需要的数据契约；完整模型和 DocumentService 后续单独迁移类型。
配置中的 `checkJs: false` 只避免递归检查旧依赖，带 `@ts-check` 的核心文件仍接受严格检查。
不对旧入口整体格式化，以便审阅行为变化。

新增的独立核心模块放入 `web/app-core/`，自动纳入 ESLint 与 Prettier。
新增复杂逻辑优先迁入模块，入口只加格式化后的装配代码。
新模块使用明确的参数或回调传入依赖，避免导入 app.js、复制全局状态或在导入时注册事件。

## 代价与后续

入口仍有编辑器、富文本、项目和插件装配代码；这轮建立边界，不声称消除全部集中状态。
迁移期间保留小型兼容包装函数，减少业务调用点变化。
后续按功能抽取编辑器文稿状态、命令面板与启动视图装配，并将类型契约推进到 DocumentService。
避免为了类型检查引入宽泛 `any` 或批量关闭诊断。

修改这些约束时新增 ADR，说明取舍和替代方案；验证结果仍放在验证文档中，并引用对应 ADR。

## 验证

`npm run check:core` 检查核心类型、lint 与格式；`npm run format:core` 统一格式。
`npm run verify` 在构建之前运行相同检查，现有 CI 因此会执行这一门禁。
`tests/app-core.test.mjs` 验证保存并发、动画等待、失败保护与命令执行边界；
现有启动、布局、输入和工作区浏览器测试验证实际装配行为。
`tests/app-core-browser.mjs` 额外验证平台事件、保存回调、损坏数据恢复，以及正文快捷键与插件编辑区的隔离。

## 考虑过的替代方案

- 整体重写入口或一次切换 TypeScript：改动覆盖面过大，会混合架构和功能回归。
- 只做全文件格式化：改善可读性，但不会划清状态和依赖边界。
- 建立新的全局 store 或事件系统接管所有业务：需要同时迁移现有业务接口，超出当前拆分范围。
