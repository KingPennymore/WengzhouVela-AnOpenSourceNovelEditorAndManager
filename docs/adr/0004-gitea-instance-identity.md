# 0004：Gitea 以服务器实例作为同步身份的一部分

状态：已采用。

## 背景

GitHub 和 Gitee 使用固定服务地址，原先只需以 provider 区分平台。
Gitea 允许用户连接多个自建实例，相同的账号名、仓库名和文件路径可能指向完全不同的文稿。

## 决定

在已有 provider 上增加 Gitea 的规范化 server 字段，沿用手动拉取、预览、提交及冲突处理。
缓存、远端关联、同步基线和凭据均纳入实例身份。固定平台保留原有身份和凭据名称，避免迁移。

允许用户明确填写 HTTPS 站点、端口和部署子路径。各个原生网络边界独立校验地址和 API 路径，
凭据按实例保存，禁止自动重定向和跳过证书检查。首版不接受 HTTP、自签名证书例外或 OAuth 登录。

Gitea 多文件提交使用它自身的批量 Contents API，每个已有文件携带 blob SHA。
提交前后准备阶段检查分支头；不将失败批次拆为逐文件请求，避免部分成功。
不宣称该 API 提供 GitHub 非强制 ref 更新的整分支比较条件，其并发边界在 GITEA.md 中记录。

## 结果

现有文稿无需迁移。多个实例的同名仓库不会混用内容或凭据，编辑器和现有同步界面可以继续复用。
增加了三个原生端保持地址规范化规则一致的维护责任；使用单元检查、浏览器检查和隔离的真实 Gitea 实例验证。
